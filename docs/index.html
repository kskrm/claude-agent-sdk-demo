文章ではなく答えだけ返すAI

Hacker News・9/16・原題: Introducing System One Models and Jev

AIを作る会社 Typesafe.ai が、これまでとはまったく違う仕組みのAI「Jev」を公開しました。人が読むための文章は一切作らず、あらかじめ決めた形の答えと「どれくらい確かか」という数字だけを返します。返事は0.07〜0.5秒で戻り、答えを出す側の料金は無料です。

そもそもの話いま話題のAIの多くは、文章を単語より細かいかたまりに分け、それを前から1つずつ予測して並べていきます。人が読む文章を作るにはこのやり方が向いていますが、順番に作るぶん時間がかかり、できあがるのはあくまで文字の並びです。プログラムがその答えを使うには書かれた文字を読み取り直す必要があり、形が崩れていたり事実でない内容が混じっていたりすると、そこで処理が止まってしまいます。
たとえるなら飲食店で注文を確かめるとき、店員さんが「ええと、こちらのお客様はコーヒーをホットで、砂糖はなしで……」と最初から順に話すのが、これまでのAIです。Jevは、伝票のチェック欄に一度で印をつけて返します。欄と選べる項目が最初から決まっているので、書き間違いが起きず、こちらも読み直す必要がありません。

使われている技術

トークンを1つずつ作る生成文章を細かいかたまりに分け、前から順に予測して並べるやり方

いまの対話型AIの標準的な作り方です。次のかたまりを予測するには直前までの結果が必要なので、必ず順番待ちが発生します。そのため答えが返るまでに3秒から329秒かかることがあり、プログラムの中で何度も呼び出す用途には向きませんでした。

並列サンプリング答えを順番にではなく、一度にまとめて出す方法

Typesafe.ai は独自の仕組みを作り、1回の問い合わせで出力をまとめて生成します。順番待ちがなくなるため応答は70〜500ミリ秒（0.07〜0.5秒）に収まり、同じ賢さを持つ大きなAIより40〜200倍速いとしています。

型安全な構造化出力答えの形をあらかじめ決め、その形どおりの値だけを返す仕組み

Jevは文章ではなく、決められた項目と選べる値に沿った答えを返します。形が決めた通りにならないことが計算のうえで起こらないため、型エラー率は0%です。受け取るプログラムは文字を読み取り直す作業も、形が崩れた場合の備えも要らなくなります。

確率つきの答え（較正）答えと一緒に「どれくらい確かか」を数字で返すこと

Jevは一つの答えを言い切らず、選べる値ごとに確からしさを付けて返します。しかも自信の高さと実際の正しさが合うように訓練されており、Typesafe.ai はこの訓練方法をRLCDと呼んでいます。自信が高いものは自動で処理し、低いものは人が見る、という使い分けができます。

何が変わる？

アプリ開発者AIの答えを読み取り直す処理や、形が崩れたときの後始末が不要になります。入力は100万かたまりで0.042ドル、出力は無料です。
一般利用者70〜500ミリ秒で返るため、入力中の候補表示や自動の振り分けなど、待ち時間が許されない画面の中でもAIの判断を使えるようになります。
情報システム部門事実でない内容が混じらず、答えごとに確からしさの数字が付くので、自信の低い判断だけを人が確認する運用を組めます。

ハルシネーションAIが事実でない内容をもっともらしく作ってしまうこと
型エラー返ってきた値の形が、決めておいた形と合わないこと

アマゾンの新AI、資料を丸ごと読める

AWS Machine Learning Blog・9/19・原題: Introducing Kimi K3 on Amazon Bedrock

中国のMoonshot AIが作った新しいAI「Kimi K3」が、アマゾンのクラウド上で呼び出して使えるようになりました。文章だけでなく画像もそのまま見て理解でき、とても長い資料や大量のプログラムを一度に読み込めるのが特徴です。同じ前置きを何度も送るときの待ち時間と料金を減らす仕組みも備えています。

そもそもの話AI（人の言葉を理解して文章やプログラムを書くソフト）を使うとき、多くの人は作った会社のサービスに接続して利用します。一方で、AIの中身にあたる設定値が公開されているものは、利用する側が自分たちの環境に置いて動かせます。Amazon Bedrockは、いろいろな会社のAIをまとめて呼び出せる窓口のようなAWSのサービスで、今回そこに新しいAIが加わりました。
たとえるなら料理のたびにだしを一から取り直すのではなく、一度取っただしを冷蔵庫に30分以上とっておいて、二品目からは使い回すようなものです。だしを取る手間（待ち時間）と材料費（料金）が二品目からぐっと下がります。とっておく分の費用は少しかかりますが、同じだしを何度も使うほど得になります。

使われている技術

オープンウェイトモデルAIの中身の数値が公開され、誰でも動かせるモデル

AIは学習でためこんだ膨大な数値（重み）のかたまりです。これが公開されていると、利用する側は自分たちの管理下でAIを動かせます。Kimi K3は重みが公開されたモデルとして初めて2.8兆個という規模に達し、前の世代のKimi K2と比べて規模あたりの効率が約2.5倍に上がっています。

コンテキストウィンドウAIが一度に読み込める文章の量の上限

AIには一度に読める量の上限があり、超えた分は扱えません。Kimi K3はここが100万トークン（文章を細かく区切って数えるときの単位）分あります。そのため大きなプログラム一式や長い資料、画像を、分割せずまとめて渡したまま作業を続けられます。

明示的プロンプトキャッシュ毎回送る前置き部分を保存して使い回す仕組み

AIには毎回同じ資料や指示を前置きとして送ることが多く、そのたびに読み直す時間と料金がかかります。使い回したい部分の区切りに印を付けると、1,024トークン以上を最低30分ためておき、次からは割引価格で使えます。Amazon Bedrockのオープンウェイトモデルでこれに対応したのはKimi K3が初めてです。

何が変わる？

アプリ開発者大きなプログラム一式や長い資料をまとめて渡せるうえ、同じ前置きは割引価格で使い回せるので、開発を助けるAIを安く作り込めます。
情報システム部門処理はAWSのデータ境界の中で行われ、データの保存も運用者の閲覧もされないため、今のセキュリティ方針を変えずに新しいAIを試せます。
運用担当者米国向けではなく全世界向けの接続先を選ぶと料金が約10%安くなるため、同じ処理でも接続先の選び方で費用を抑えられます。

オープンウェイトAIの中身の数値が公開され、自前の環境でも動かせること
トークンAIが文章を数えるときの単位。文字や単語のかたまり
コンテキストウィンドウAIが一度に読み込める文章量の上限。Kimi K3は100万トークン
プロンプトキャッシュ毎回送る前置きを保存して使い回し、時間と料金を減らす仕組み

長い作業を最後までやり切るAIが登場

AWS Japan Blog・9/18・原題: Claude Fable 5.1 が Kiro で利用可能になりました

AWS の開発ツール Kiro で、新しい AI「Claude Fable 5.1」が2026年9月18日から使えるようになりました。長い時間をかける作業でも最初に決めた計画を終盤まで保ち、不具合の見かけの症状ではなく、コードの中にある原因そのものを突き止めます。使えるのは、企業向けの管理設定を有効にしている顧客です。

AIに開発を任せる話Kiro は AWS が提供する、プログラムを書く仕事を AI に任せるための道具です。人が一行ずつ書く代わりに、やりたいことを伝えると AI が手順を考えて作業します。ただし作業が長くなるほど、AI は最初に決めた方針を忘れたり、話が脱線したりしがちでした。今回入った Claude Fable 5.1 は、その「長い作業を最後までやり切る」ところを狙った AI です。
引っ越しにたとえると大きな引っ越しを手伝ってもらう場面に似ています。これまでの手伝い役は、午前中は指示どおりでも、夕方には「本は書斎、服は寝室」という朝の約束を忘れ、箱を適当な部屋に置き始めました。新しい手伝い役は、夕方になっても朝の約束を覚えています。しかも「この置き方では入らない」と分かったら、押し込み続けずに別のやり方に切り替えます。

図で見る

これまで

これから

「これまで」と「これから」を見比べると、作業が長引いたときの違いが分かります。

使われている技術

エージェント目的を伝えると自分で手順を考えて実行するAI

人が一行ずつ指示する使い方と違い、エージェントは「このバグを直して」と伝えるだけで、調べる・直す・確かめるという手順を自分で組み立てます。手順が長くなるほど途中で方針を見失いやすく、そこを崩さずに走り切れるかが、実際の仕事で使えるかどうかの分かれ目になります。

コンテキストウィンドウAIが一度に覚えていられる情報の量

Fable 5.1 は1Mトークン（トークンは文章を数えるときの、文字のかたまりの単位）まで扱えます。ここに入りきらない分は覚えていられないため、大きなプログラムをまとめて見ながら作業するには、この量の大きさがそのまま仕事の範囲の広さになります。

スペック駆動ワークフロー先に仕様を決め、それに沿って作業を進めるやり方

Kiro は作業を始める前に「何を作るか」を文章でまとめ、その内容に沿って進めます。Fable 5.1 では、ある進め方が失敗したと判断した場合に、行き詰まった方向で繰り返し試すことを避けます。同じ壁に何度もぶつかって時間を使う事態を防ぐためです。

何が変わる？

アプリ開発者バグ修正やリファクタリング（動きを変えずにコードを整理し直すこと）での正確さが上がり、何段階もある長い作業も最後まで到達しやすくなります。
情報システム部門AWS の管理コンソールで Model Governance を有効にし、モデル一覧で Fable 5.1 をオンにする作業が必要です。対象はエンタープライズ顧客に限られます。
利用コストの管理者Fable 5.1 はクレジット乗数が6倍です。同じ作業でも消費量が6倍として数えられるため、どの場面で使うかをあらかじめ決めておく必要があります。

KiroAWSが提供する、AIに開発作業を任せるための道具
コンテキストウィンドウAIが一度に覚えていられる情報の量
トークンAIが文章を数えるときの単位。文字のかたまり
Model Governance組織内でどのAIを使ってよいかを管理する設定
クレジット乗数利用量を数えるときにかけ算される倍率

次の一歩 → AWS管理コンソールのKiro設定でModel Governanceを有効にし、Fable 5.1を選びます。

AIの待ち時間が約2秒に短縮

AWS Machine Learning Blog・9/19・原題: The new AgentCore runtime: Elastic, optimized, and consistently fast starts

AWSが、AIエージェントを動かすための土台「Amazon Bedrock AgentCore」の新しい実行環境を発表しました。これまでは中身が大きいと立ち上がりに30秒近くかかることもありましたが、新しい環境では中身の大きさにかかわらず、4回に3回は約2秒で立ち上がります。使い終わった作業スペースを回収して、その分だけ料金に反映する仕組みも入りました。

そもそもの話AIエージェント（目的を伝えると、人が一つずつ指示しなくても自分で手順を考えて実行するAI）を動かすには、それを置いて動かすコンピューターが必要です。AWSはその置き場所を貸し出していて、利用者は使った時間と作業スペースの量に応じてお金を払います。ただし、頼まれてから置き場所を用意して立ち上げるまでには待ち時間が生まれます。試作のうちは我慢できても、お客さん相手に使うと、この待ち時間がそのまま体験の悪さになります。
たとえるなら飲食店の開店準備に似ています。毎朝ゼロから仕込むと、材料が増えるほど開店までの時間が延びてしまいます。新しい仕組みは、仕込みが終わった状態をそのまま丸ごと保存しておき、開店のたびにその状態を取り出します。材料の量が増えても保存した中身の大きさはほとんど変わらないので、開店までの時間はいつも同じです。

図で見る

使った分冷えた作業スペースは回収される

左が新しい仕組みが入る前、右が入った後の姿です。

使われている技術

AIエージェント目的を伝えると自分で手順を考えて実行するAI

チャットのAIは質問に答えるだけですが、エージェントは調べ物や申し込みなどの作業を自分で順番に進めます。人の代わりに動き続けるため、いつでも動かせるコンピューターの置き場所が必要になり、その置き場所の速さと料金が使い勝手を大きく左右します。

コールドスタート置き場所を一から立ち上げるときの待ち時間

止まっている状態から動く状態にするには、置き場所を用意して中のプログラムを読み込む必要があります。これまでのAgentCoreでは、中身が200MBなら約5.4秒、2GB近くになると30秒近くかかっていました。人が画面の前で待つ用途では致命的な長さです。

スナップショット立ち上げ終わった状態をそのまま保存したもの

新しい実行環境は、置き場所を一度立ち上げて正常に動くと確認できた時点の状態を、丸ごと保存します。次からは一から立ち上げずに、この状態を戻すだけで済みます。保存するときに一時的なデータを取り除くため、中身が大きくなっても保存物の大きさはほとんど変わりません。

使った分だけの課金実際に使った作業スペースの分だけ払う仕組み

これまでは一度使った最大量を、そのやりとりが終わるまで確保し続け、その分を払い続けていました。新しい実行環境は小さく始めて、必要になった分だけ足していきます。使い終わって冷えた分は回収され、単価は上がるものの、払う量そのものが減ります。

何が変わる？

アプリ開発者起動を速く見せるために予備の環境を常に待機させる工夫が要らなくなり、待ち時間の調整ではなく中身の作り込みに時間を使えます。
サービス運営者利用者を待たせる時間が30秒近くから約2秒にそろうため、その場で応答が返る対話型の機能でも、途中で離脱されにくくなります。
情報システム部門一番多く使った量を使い終わるまで払う形から、実際に使った分を払う形に変わるため、使い方にムラのあるエージェントほど請求額が読みやすくなります。

コンテナイメージ動かしたいプログラムと必要な部品を一つにまとめた荷物
コールドスタート止まった状態から動き出すまでにかかる待ち時間
P754回に3回はこの時間内に収まる、という目安の値
セッション話しかけてから終わるまでの、ひとまとまりのやりとり

審査を通った研究者だけ、AIの制限を解除

Anthropic News・9/17・原題: Introducing the Life Sciences Verification Program

Anthropicは9月17日、生命科学（生き物のしくみを調べる研究）の専門家に向けて、審査を通った人だけAIの答えを断る制限をゆるめる仕組みを始めました。これまでAIは、悪用を防ぐために生物学の質問を幅広く断っていました。これからは研究実績や安全管理の体制を先に確かめ、確認できた組織にだけ許可を出します。

なぜ断られるのかAIは生物に関する質問の一部を、はじめから断るように作られています。病気やウイルスのしくみに詳しい知識は、悪用されると人を傷つける道具にもなり得るからです。ただこの線引きは機械的で、正当な研究者の質問まで巻き込んで断ってしまいます。そこで「誰が何のために聞いているのか」を先に確かめ、確認できた相手には断りを減らす、という発想が出てきました。
たとえるなら薬局街の薬局では、強い薬を誰にでも売ることはしません。とはいえ、本当に必要な患者まで買えないのでは困ります。そこで医師の処方箋を確かめ、確認できた人にだけ渡します。今回の仕組みも同じで、AIが誰にでもは渡さない答えを、所属と目的を確かめた研究者にだけ渡すようにしたものです。処方箋の有効期限のように、許可にも期限があります。

あとで点検30日保存し目的どおりか確かめる

左が従来のやり方、右が審査を通った研究者に適用される新しい流れです。

使われている技術

セーフガード（安全制御）AIが危ない質問に答えないようにする仕組み

AIの本体は学習した知識をそのまま出そうとするため、外側に「この話題には答えない」という関所を置いています。生物学は医療にも兵器にも使えるので、この関所がとりわけ厳しく働きます。今回のプログラムは、審査を通った相手に限ってこの関所をゆるめるものです。

グラント（利用許可）誰が何にAIを使ってよいかを定めた許可証

許可は2種類あります。基礎研究から製造、臨床開発、規制対応、投資までをチーム単位で広くカバーする標準利用グラントは、1年ごとの更新です。生物学の制限をすべて外す高リスク利用グラントは、チームではなく研究プロジェクト1件ごとに与えられ、6カ月ごとに更新します。

オフライン監視その場で止めず、後からやり取りを点検するやり方

これまでは質問が来た瞬間に危ないかどうかを判定し、その場で止めていました。このプログラムでは判定を後ろにずらし、申請した目的どおりに使われているかを後から確かめます。そのためやり取りは30日間保存されますが、この記録は厳重に分けて管理され、モデルの学習には使われません。

何が変わる？

生命科学の研究者ウイルスや遺伝子についての質問が断られにくくなります。所属や研究実績、倫理面の審査を通ることが条件で、標準の許可は1年ごとに更新します。
企業の情シス部門申請はチームや組織の単位で行い、EnterpriseプランかTeamプランが必要です。やり取りが30日間保存されるため、社内の情報管理の取り決めを見直す必要があります。
一般の利用者今のところ個人向けプランは対象外で、普段の使い方は変わりません。制限をゆるめる相手を審査で絞り込むことで、誰でも使える窓口の安全は保たれます。
